# Пропозиція: Canonical Numeric Profile v0 (CNP-0)

**Статус:** proposal для зняття blocker RFC-0004 (Tranche A3)
**Сумісність:** розширює §5.1.1–§5.1.2; не чіпає store, CID transport, warrant hash prefix
**Критерій успіху:** два незалежні encoder’и на різних мовах дають byte-identical digests на спільному fixture corpus; третій verifier лише читає

## 1. Рішення, яке знімає blocker

Зафіксувати **один** federation-wide numeric profile для digest input:

| Клас значень | Canonical форма | Примітка |
|---|---|---|
| Цілі | signed integer в єдиному integer domain профілю | без leading zeros у text-form; нижче — бинарний варіант |
| Раціональні | `ratio { num, den }` | `den > 0`, `gcd(|num|,den)=1`, нуль лише `0/1` |
| Fixed-point | `fixed { value, scale_id }` | `scale` **не** per-value; лише per-domain через registry |
| enum / symbol | `sym` + content-addressed symbol table або inline string per §5.1.1 rule 5 | без Unicode normalization |
| Байтові blob | raw bytes + length | для LUT, proof objects |
| Float / NaN / ±Inf | **заборонені** в canonical digest input | internal compute дозволений |

**A3 resolved as:** *integers + reduced ratios + domain-scoped fixed; no IEEE float on the wire.*

Це саме той вибір, який RFC-0004 уже називає admissible; пропозиція робить його **обов’язковим default profile**, а не відкритим меню.

## 2. Нормативні правила (MUST)

### 2.1 Integer domain

- Один signed integer domain для профілю: **двокомплементарний, ширина зафіксована в profile id**.
  Рекомендація для v0: **i128** як *abstract* range; на дроті — CBOR/canonical binary або JCS-з сумісним decimal **лише якщо** всі impl погоджують exact digit string (краще binary profile, див. §3).
- Overflow у canonical encode = **validation error**, не wrap (wrap дозволений лише всередині domain ops, якщо domain це declares).

### 2.2 Ratio

Як у §5.1.2, підняти з «admissible» до **required reduction**:

1. `den > 0`
2. `gcd(|num|, den) == 1`
3. zero = `{num:0, den:1}` only
4. encode відхиляє нескорочені форми (не «поправляє мовчки» на decode path без нового digest — producer MUST reduce before hash)

### 2.3 Fixed-point

1. `scale` належить `ScaleRegistry` (content-addressed): `{ scale_id, radix: 10|2, exponent, unit? }`
2. Усі points одного state domain ділять один `scale_id`
3. Зміна scale = **новий domain** + translation loss, не in-place upgrade
4. Equality — на `value` при однаковому `scale_id`; cross-scale compare лише через declared translation

### 2.4 Probability simplex (якщо domain admitted)

- Компоненти: ratio **або** fixed з shared scale
- Валідація: exact \(\sum = 1\) (ratio) або \(\sum value_i = scale\) (fixed)
- Float summation «майже 1» — non-conforming

### 2.5 Константи (π, e, √2, …)

Три дозволені шляхи; host `libm` — **не** шлях:

| Шлях | Коли | Identity |
|---|---|---|
| **P1. Symbolic sink-avoidance** | предикат можна переписати без константи (`x>√2` → `x²>2`) | терми / rules content-addressed |
| **P2. Pinned constant object** | numeric sink неминучий | `ConstRef = H(canonical bytes of digits/table)` в domain descriptor |
| **P3. Discrete surrogate** | кути/фази | `Circle2n`, equality на індексі |

Будь-який domain, що використовує π у digest path, MUST назвати P1/P2/P3. Відсутність = reconstruction на irreversible boundary (§7.0.3 spirit).

### 2.6 Тригонометрія / коло

- Не частина numeric scalar profile.
- Окремий optional domain family, наприклад `circle2n/v1`:
  - `n` зафіксований у domain id (рекомендований default profile: **n=8 → 256**)
  - ops: `(a+b) mod 2^n` exact
  - optional `sin_lut` / `cos_lut`: fixed table, **hash LUT ∈ domain descriptor**
  - equality для direction: **angle index**, не `lut_cos(a) == lut_cos(b)`
- Export у «радіани» = translation + loss profile, не identity

### 2.7 Quantize sink (float → canonical)

Якщо internal float існує:

1. MUST назвати `QuantizeMode`: `trunc_toward_zero` | `round_ties_even` | `reject`
2. Mode ∈ translator/domain descriptor
3. Fixtures MUST включати boundary values (±, ties)
4. За замовчуванням для irreversible path: **`reject`**, якщо значення вже не exact-representable

## 3. Wire encoding (мінімум, щоб два impl зійшлися)

Blocker знімається лише разом із **однією** canonical serialization. Пропозиція:

**CNP-0-BIN** (перевага) або **CNP-0-JCS** (якщо треба text-first як у warrant).

### Рекомендація

- **Digest-facing:** deterministic binary (CBOR definite-length, canonical map key order already required by §5.1.1, або length-prefixed tags як у existing canon-vectors).
- **Human/debug:** projection, не identity.

Якщо лишаєтесь на JSON/JCS (ближче до warrant):

- числа лише як integers у JSON number **або** ratio/fixed як objects (не як decimal strings з крапкою)
- заборонені: `1e3`, `1.0`, leading zeros
- ratio/fixed — objects з обов’язковими ключами в fixed order для JCS

Окремим MUST: **profile id** входить у digest input (`cnp-0`), щоб зміна профілю змінювала references (§5.1.1 rule 6).

## 4. Що явно *не* блокує Tranche A

Залишити open (не blocker):

- повний CAS для √2, мінімальні поліноми
- вибір n∈{8,10,16} для всіх circle domains (достатньо механізму; один default fixture domain)
- ML embedding spaces (окремий approx domain пізніше)
- IPLD як store
- оптимальність ATP для gcd

## 5. Мінімальний fixture corpus (definition of done)

Щоб вважати blocker знятим умовно, MUST пройти:

1. **Integers:** 0, 1, -1, i128 edges (або declared max)
2. **Ratio:** `1/3`, `2/4` rejected, `-1/3`, `0/1` only zero
3. **Fixed:** same value different scale_id → different ref
4. **Simplex:** `[1/3,1/3,1/3]` accepted; float-ish not present
5. **Cross-impl:** Python + second language, identical full digests
6. **Const pin:** domain with pinned π table; mutate one byte → different domain ref
7. **Circle256:** rotate 64 steps; equality by index; LUT optional but hashed if present
8. **Quantize:** ties-even vector shared; reject-mode refuses non-representable on irreversible fixture

Без пунктів 5 і 8 «вибір зроблено» лишається прозою.

## 6. Текстові правки до RFC-0004 (змістовно)

1. **§5.1.2** — замінити «Selecting between these remains Tranche A3's decision» на:
   > Tranche A3 selects **CNP-0**: reduced ratios and domain-scoped fixed-point; IEEE binary floating point MUST NOT appear in canonical digest input. Profile id `cnp-0` is part of the encoding identifier (§5.1.1 rule 6).

2. Додати **§5.1.3 Canonical Numeric Profile v0** — таблиця з §1–2 цієї пропозиції.

3. Додати **§5.1.4 Named constants and transcendental sinks** — P1/P2/P3.

4. Додати **§5.1.5 Optional discrete circle domains** — не normative для core A, але normative *if implemented*.

5. У **RFC-0003 §0 / document set** — змінити:
   > RFC-0004 is the blocker → RFC-0004 CNP-0 selected; remaining open problems are domain-family admissions, not identity.

6. У **§17.1 / implementation slice** — first tests прив’язати до corpus §5; owner substrate для encoder — trinity (як у таблиці), second impl — обов’язковий gate перед «conforming federation».

## 7. Умовність зняття (важливо)

Blocker знімається **умовно**:

```text
UNBLOCKED when:
  - CNP-0 text merged in RFC-0004
  - canon-vectors extended with §5 corpus
  - ≥2 independent encoders agree bit-exact
  - verifier-only third path rejects non-reduced ratio

NOT CLAIMED:
  - all state domains exist
  - federation handshake works
  - π "solved" for mathematics
  - float internal compute forbidden
```

Якщо немає другої реалізації — це **spec choice**, не **unblocked protocol**. Краще сказати *A3 decided, A3-interop pending*, ніж знову перепродати hash.

## 8. Сумісність із integer-first практикою стеку

| Пріоритет | Правило |
|---|---|
| 1 | Не ділити раніше, ніж треба; тримати ratio до sink |
| 2 | Предикати з √2/π переписувати алгебраїчно, де можливо |
| 3 | Кути — `Circle2n`, не радіани в canonical |
| 4 | LUT/const — pinned bytes у domain id |
| 5 | Float — internal only + declared quantize |

Це узгоджує Σ-GLYPH/warrant (int/ATP/deterministic) з RFC-0004, не вимагаючи CAS-всесвіту на день один.

## 9. Ризики пропозиції (записати в open problems, не ховати)

1. **i128 vs « unbounded big-int »** — big-int простіший математично, гірший для ATP/memory bound; i128 потребує explicit overflow policy.
2. **JSON numbers** — поганий носій для i128; binary profile уникає.
3. **gcd cost** — adversarial large coprime num/den; потрібен admission bound (max bitwidth) у profile.
4. **Circle256** спокуса видати за S¹ — mitigation: capabilities table empty for Riemannian claims.
5. Екосистема ML ігноруватиме — ок; embeddings = окремий lossy domain пізніше.
